## Problem Statement

The M11 onboarding tour (`tutorial-*` family) was built on a **wrong architectural premise** —
that `/tutorial-getting-started` **dispatches the arm skill inline** (same conversation). The
operator's specified flow (origin session `fd4a9b17`, 2026-07-22, human turns 49–55; now the
authoritative doc `docs/lessons/tutorial-tour-session-chain-flow.md`) is instead a **chain of real
session boundaries**: getting-started (session A) recommends `auto` mode, asks the fork, **`cd`s the
user to the target dir, points them to the right `***-tour` skill, and tells them to `/exit`** — it
does **NOT** drive the tour. The arm skill is then **always entered directly** in a fresh session:
first run in **stepping** (session B → handoff → exit → session C restore → graduate → exit), replay
in **autopilot/FSD** (session D). Because the arm is always a direct entry, the discriminator is
**first-run vs. replay**, resolved by the arm **asking one line on entry**; drive mode (a numbered
1–4 menu, not a slash command) is **presented by the arm itself on the replay run** (the first run
defaults to stepping and never mentions modes exist until the Step-8 graduation).

This re-plan (F23 back-loop) makes the session-chain flow the **foundation** and re-sequences the
previously-planned pieces (brownfield git-safety, mode-aware graduation, scaffold re-home) on top of
it. It **supersedes** the prior 4-phase tree (whose Phase-1 replay copy assumed the dispatch-inline
model and is re-cut here, not approved-then-patched). All copy remains **NAMED close beats /
pre-flight**, never staged runs (the tour must never demo autopilot live — that would hide beat B).
Prose + one `git mv` (scaffold); **no `transitions.md` change** (tutorial-* emit no transition).
WP7e later pins + scenario-tests this ACCEPTED copy, across BOTH entry paths (see Notes).

**[Problem statement unchanged — F12 re-check 2026-07-23]** The verify-human rejection of
P1.verify-human.5 refined a *sub-detail* of the point+cd+exit conversion, not the root problem:
session A (getting-started) doesn't itself run anything, so the `auto` permission-mode recommendation
should NOT be a standalone upfront Step 1 in session A — fold the launch command into the cd+relaunch
instruction (where the arm session is actually launched), keeping a short trimmed reassurance note.
The root problem (convert getting-started to point+cd+exit) is unchanged; this is placement, not
root-cause shift. 3/4 sibling leaves (.1–.4) already operator-approved — not re-touched.
